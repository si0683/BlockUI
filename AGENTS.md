# AGENTS.md — rules for AI coding agents

LightWebsiteUi (since 4.0.0) is a **project starter**, not a runtime library: the npm package `create-lightwebsiteui` copies `template/` (Astro + React + Tailwind CSS + shadcn/ui + Lucide + Motion) into a new folder and runs `npm install`.

- `bin/create.mjs` — the CLI. Node ≥ 22.12, **no dependencies** (only `node:` modules). npm never publishes `.gitignore`, so the template keeps it as `template/_gitignore` and the CLI renames it.
- `template/` — a working Astro project. Work on it in place: `cd template && npm install && npm run dev` (node_modules, dist, .astro and package-lock.json are git-ignored and excluded from the package).
- shadcn/ui components in `template/src/components/ui/` come from the CLI only: `npx shadcn@latest add <name>` inside `template/`, then `npm run format`. Never hand-write them. Update the component list in both READMEs and `template/README.md`.
- `template/AGENTS.md` is the guide for agents working in the user's new project — keep it in sync with the template (React islands in Astro: no shared context, no `asChild`, `client:*`).
- Template texts are Russian (`lang="ru"`), code comments English.
- Before a release, check the whole path: `npm pack`, then `npx ./create-lightwebsiteui-<v>.tgz "Test Site"` in a temp folder, and in the new project `npm run build`, `npm run typecheck`, `npm run lint`, `npx prettier --check .`; open `npm run dev`, test the order dialog, mobile menu, FAQ, theme toggle at 375 px and 1280 px.
- Versions: `version` in package.json + CHANGELOG.md + tag `vX.Y.Z`. Published tags are never changed.
- `index.html` in the root is the GitHub Pages landing (static, no build): Russian, light/dark theme, violet-pink-amber palette.
- Old tags v1.0.0–v3.2.1 hold the former CDN library (`blockui.js` / `lightwebsiteui.js`). Lesson repos (CreateSite01PROMT and the lesson sites) pin them through jsDelivr — do not delete those tags.
- `PROMT.md` (Russian fill-in brief for AI assistants) lives in the root for download and as `template/PROMT.md` in every new project — keep both copies identical and in sync with the template (stack, scripts, file names).
- Optional CMS: `cms/<name>/` (now only `payload`) = `cms.json` (title, database choices with adapter package and DATABASE_URL, Payload version, site scripts, docs to append), `app/` (the Payload 3 + Next.js app, copied to `<project>/cms`; `.gitignore` stored as `_gitignore`), `site/` (copied over the site: `src/data/content.ts`, `src/lib/leads.ts`, `PAYLOAD.md`), `db/<db>/` (copied over `cms/`: `src/db.ts`, `docker-compose.yml`), `append/` (added to AGENTS.md, README.md, PROMT.md, .gitignore — the last one stored as `_gitignore`). `bin/create.mjs` handles `--cms` / `--db`, writes `cms/.env` with a random `PAYLOAD_SECRET` and the site `.env` with `PUBLIC_CMS_URL`, and installs both packages.
- The site template has two seams the CMS replaces: `src/data/content.ts` (`getContent()`, used by `src/pages/index.astro`) and `src/lib/leads.ts` (`sendLead()`, used by the order dialog). Keep their signatures stable. Site tooling ignores `cms/` (tsconfig exclude, ESLint, Prettier).
- Payload app: collections in `app/src/collections`, global `app/src/globals/Site.ts`, seed `app/src/seed.ts` (mirrors `template/src/data/site.ts`), access helpers `app/src/access.ts`, CORS/CSRF from `SITE_URL`. After changing fields run `npm run generate:types` in a test project and copy `src/payload-types.ts` back. Payload packages are pinned to the version in `cms.json` / `app/package.json`; upgrade them together.
- Release check for the CMS: create projects with `--cms=payload --db=sqlite` and `--db=postgres` (Docker on a free port), `cd cms && npx tsc --noEmit && npm run build`, start `npm run cms` and `npm run dev`, then: seed appears, site shows CMS content, an edit in the CMS shows up on reload, the order form creates a lead (201), leads are not readable anonymously (403), honeypot is rejected (400).
- Online payment (`--pay`, needs `--cms=payload`): `cms/payload/pay/common/` (app: `Orders` collection with `/api/orders/pay|webhook|status`, `addons/payments.ts` that registers it; site: `plan-action.tsx`, `pay-dialog.tsx`, `payment-status.tsx`, `lib/payments.ts`, `pages/thanks.astro`), `cms/payload/pay/<provider>/` (app: `payments/provider.ts` replacing the no-op one of the base; site: `PAYMENTS.md`), `cms/payload/pay/append/` (AGENTS/README/PROMT). `cms.json` → `pays` lists providers with their `.env` lines. Seams in the base: `template/src/components/site/plan-action.tsx` and `app/src/addons/payments.ts`. Types and the admin import map are regenerated by the installer after `npm install` (`generate:types`, `generate:importmap`).
- Payment rules: price only from the plan's `amount`; return URL only to `SITE_URL` origins; status only from the provider API (webhook and thanks page just trigger `syncPayment`); Stripe webhooks need a valid `Stripe-Signature` when `STRIPE_WEBHOOK_SECRET` is set. Provider calls use plain `fetch`, no SDK packages; `YOOKASSA_API_URL` / `STRIPE_API_URL` allow a mock server.
- Release check for payments: create `--pay=yookassa` and `--pay=stripe` projects, point the API URL to a mock that implements create/get and a "pay" redirect, then: Pay button only on plans with an amount, redirect → `/thanks` shows "оплата прошла", the client cannot change the amount, foreign returnUrl / honeypot / plan without amount → 400, anonymous orders read/create → 403, a real webhook marks the order paid, a forged one does not, Stripe unsigned / wrong / stale signatures → 400.
- Two-factor sign-in (`--2fa[=required]`, needs `--cms=payload`): `cms/payload/twofa/` — `app/src/addons/security.ts` (payload-totp, `forceSetup` from `TOTP_REQUIRED`, issuer from `TOTP_ISSUER`), `app/src/proxy.ts` (`x-pathname` header for the plugin on Next 16), `app/src/scripts/reset-2fa.ts` (+ `reset-2fa` script for a lost phone), `append/` (AGENTS/README/PROMT/PAYLOAD). `cms.json` → `twofa` holds the package version, modes and scripts. Seam in the base: `app/src/addons/security.ts` (plugins go last in `payload.config.ts`).
- payload-totp wraps the access of everything: anonymous requests are refused unless the operation is marked with `custom.totp.disableAccessWrapper` — the base collections already carry `publicReadCustom` / `publicCreateCustom` from `app/src/access.ts`; any new public collection must too.
- `csrf` must include the CMS's own origin (`CMS_URL`, default `http://localhost:3000`) next to `SITE_URL`: the admin panel sends cookies with that Origin; without it saving in the admin panel fails.
- Release check for 2FA: with `--2fa=required` — public reads, leads and `/api/orders/pay` work anonymously; a signed-in user without the app is refused until `/api/setup-totp`; after a new login, refused until `/api/verify-totp`; wrong codes rejected; the admin login shows the code page (no redirect loop) and saving works in the browser; `npm run reset-2fa -- email` removes the app. With `--2fa` (optional) a user without the app works normally.
- The base CMS always has `src/payments/types.ts`, a no-op `provider.ts` (`configured() === false`) and `sync.ts` (`syncPayment` for every payable collection: `orders`, `shop-orders`), so plans and the shop share one payment path.
- Shop (`--shop`, needs `--cms=payload`): `cms/payload/shop/` — app: `Categories`, `Products`, `ShopOrders` (`/api/shop-orders/checkout`, `/status`), `lib/slug.ts`, `addons/shop.ts` (collections + demo seed + "Каталог" menu link); site: `data/shop.ts`, `lib/cart.ts`, `components/shop/*`, `layouts/shop.astro`, pages `catalog/`, `product/[slug]`, `cart`, `order`, `SHOP.md`; `append/`. Seam in the base: `app/src/addons/shop.ts` (`shopCollections`, `shopSeed` run from `onInit`).
- Release check for the shop: catalog, category, product, cart and order pages return 200 with the CMS up and build with it down; add to cart → checkout → (with `--pay` mock) payment → `/order/` shows the status; more than stock / out of stock → 409, empty cart / no e-mail with payment / foreign returnUrl → 400, client prices ignored, anonymous shop-orders read/create and product edits → 403.
- Exchange with 1C (`--1c`, needs `--shop`): `cms/payload/onec/` — app: `collections/ExchangeLog.ts`, `addons/integrations.ts` (`GET/POST /api/1c/exchange`), `onec/{exchange,catalog,sale,auth,storage,xml}.ts`; site: `1C.md`; `append/`. `cms.json` → `onec` holds the fast-xml-parser version and env lines (the installer generates `ONEC_PASSWORD`). Seams in the base: `app/src/addons/integrations.ts` (`integrationCollections`, `integrationEndpoints` → config `endpoints`), `externalId` on categories/products/order items, `exportedAt` on shop orders, hidden `syncedImages` on products, `/.1c-exchange` in `cms/.gitignore`.
- Release check for 1C: simulate the 1C HTTP sequence (checkauth with wrong/no password → failure, init, file in parts, `../` names → failure, import repeated while `progress`, offers with several price types, warehouses and `#characteristics`; then sale init/query/success and a windows-1251 order file): categories nested, properties resolved, picture uploaded once, new products hidden until a price, zero price / "Удален" hidden, full catalog hides missing 1C products but not manual ones, query escapes XML and stops after success, statuses paid/canceled applied.
