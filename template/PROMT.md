## 4. Технические решения

Базовый стек менять нельзя: Astro + React + Tailwind CSS 4 + shadcn/ui + lucide-react + Motion + TypeScript. Остальное выбери по типу проекта:

- **Статический сайт** (лендинг, сайт компании, блог, портфолио): Astro собирает HTML. Формы отправляются во внешний сервис или в serverless-функцию. Хостинг — GitHub Pages (workflow уже есть) или любой статический хостинг.
- **Приложение, сервис, SaaS:**
  - серверный режим Astro: адаптер `@astrojs/node`, `export const prerender = false` на динамических страницах;
  - формы — Astro Actions, проверка данных — `zod`;
  - база данных — Drizzle ORM: SQLite/libSQL для старта или PostgreSQL;
  - вход — Better Auth;
  - секреты — только в `.env` через `astro:env`, в репозиторий их не коммитить;
  - хостинг — VPS или Docker. GitHub Pages сервер не поддерживает.
- Интерактивные части — React-компоненты с `client:load` или `client:visible`. Всё остальное — статический HTML без JavaScript.

- **Вход в админку с кодом (2FA):** [ ] не нужен [ ] по желанию каждого (`--2fa`) [ ] обязательно для всех (`--2fa=required`) — только вместе с Payload
- **Онлайн-оплата:** [ ] не нужна [ ] ЮKassa (`--pay=yookassa`, Россия) [ ] Stripe (`--pay=stripe`, клиенты за рубежом) — только вместе с Payload
- **CMS (админка для контента и заявок):** [ ] не нужна — тексты в коде [ ] Payload CMS (`--cms=payload`): база [ ] SQLite — сайт компании, 1–2 редактора [ ] PostgreSQL — SaaS, магазин, много пользователей

Мои пожелания или ограничения: «например: только российские сервисы / база PostgreSQL уже есть / хостинг Timeweb / бюджет на сервисы 0 ₽»

## 7. Качество

- Адаптивность от 320 до 1920 px, без горизонтальной прокрутки, сначала мобильная версия.
- SEO: уникальные `title` и `description`, Open Graph, `sitemap.xml` (`@astrojs/sitemap`), `robots.txt`, семантические заголовки, `alt` у картинок.
- Скорость: Lighthouse 90+ на мобильном, картинки через `astro:assets` (`<Image>`), минимум JavaScript.
- Доступность: контраст, подписи у полей, работа с клавиатуры, `prefers-reduced-motion`.
- Формы: проверка полей, понятные ошибки, защита от спама (honeypot или капча), состояние «отправлено».
- Безопасность (для приложений): пароли только через Better Auth, проверка прав на сервере, защита от CSRF/XSS, лимиты запросов на формы.
- Светлая и тёмная темы выглядят одинаково аккуратно.

## 8. Как работать

1. Прочитай `AGENTS.md`, `README.md` и структуру `src/`.
2. Задай мне до 10 уточняющих вопросов — только о том, без чего нельзя начать. По остальному прими разумные решения и перечисли их.
3. Покажи план: страницы, компоненты, данные, новые зависимости (с причиной для каждой), этапы. Жди моего «ок».
4. Делай по этапам. Каждый этап должен завершаться рабочим состоянием:
   - этап 1 — структура и дизайн-система (цвета, шрифты, общие компоненты);
   - этап 2 — страницы с контентом;
   - этап 3 — функции (формы, вход, база, оплата);
   - этап 4 — SEO, скорость, полировка.
5. Демо-контент шаблона (`src/data/site.ts`, «Студия Лайт») замени на мой проект. Ненужные демо-компоненты удали.
6. Компоненты shadcn/ui добавляй только командой `npx shadcn@latest add <name>`, иконки — из `lucide-react`, анимации — из `motion/react`.
7. После каждого этапа запускай `npm run build`, `npm run typecheck`, `npm run lint`, `npm run format` и исправляй ошибки. Затем кратко опиши, что сделано и как проверить.
8. В конце обнови `README.md`: как запустить, где менять тексты, как выложить, какие переменные нужны в `.env`.
